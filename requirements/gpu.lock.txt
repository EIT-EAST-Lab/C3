# C3 GPU tier lock file

# What this is
#   A current, internally consistent training stack: the vLLM, Ray and DeepSpeed
#   environment needed to run the paper's training and evaluation workflows,
#   resolved against the newest vLLM release. `pip check` passes on it.
#   To reproduce the published numbers against the environment that produced
#   them, use requirements/gpu-paper.lock.txt instead.
#
# How it was generated
#   python -m venv .venv && . .venv/bin/activate
#   python -m pip install -U pip
#   python -m pip install "vllm==0.28.0"
#   python -m pip install deepspeed "ray[default]" peft accelerate torchdata wandb
#   python -m pip install PyYAML numpy sympy regex word2number pylatexenc pytest \
#                         datasets transformers huggingface_hub pyarrow matplotlib math-verify
#   python -m pip freeze     # the editable self-reference line was removed
#   Date: 2026-09-07 (UTC). Resolved on Linux x86_64 with CPython 3.11.14.
#   vLLM is pinned first on purpose: it is the package that pins torch, and
#   letting the resolver choose it last sends it backtracking through every
#   release.
#
# How to install it
#   python -m pip install -r requirements/gpu.lock.txt
#   python -m pip install -e . --no-deps
#   No extra index is needed: torch 2.13.0 on PyPI is the CUDA build, and it
#   pulls the CUDA 13 runtime wheels listed below.
#
# What has been verified, and on what
#   Verified on a CPU-only machine: installation resolves and completes,
#   `python -m pip check` is clean, `import torch, ray, deepspeed, transformers`
#   succeed, `import openrlhf.cli.train_ppo_ray` with TRANSFORMERS_NO_TF=1
#   succeeds, the full unit test suite passes, and
#   `scripts/30_smoke/smoke.sh --tier gpu` passes including the import stage.
#
#   GPU EXECUTION IS NOT YET VALIDATED. The following need a real NVIDIA GPU and
#   are unverified against this version set:
#     - vLLM engine sleep and wake, and the weight synchronization path in
#       openrlhf/trainer/ray/vllm_engine.py;
#     - a DeepSpeed ZeRO-2 training step;
#     - the FlashAttention path (attn_implementation="flash_attention_2");
#     - end to end numerical agreement with the published results.
#   Treat this file as a starting point for a GPU bring-up, not as a validated
#   training environment.
#
# What is deliberately absent
#   flash-attn: never imported directly, selected through the
#     attn_implementation="flash_attention_2" string. It builds from source and
#     needs a CUDA toolchain, so it is an optional extra: pip install -e ".[flash]"
#     --no-build-isolation.
#   xformers: the only release that resolves against this torch would drag the
#     resolver away from vLLM's own pin, and nothing in this repository imports
#     it. It was in the paper environment, where it is the reason `pip check`
#     fails there.
#   evalplus: its Google client chain pins protobuf below 6, while the CUTLASS
#     libraries that vLLM 0.28 depends on need protobuf 6.30.2 or newer. The two
#     cannot coexist. evalplus is only needed to prepare the MBPP+ dataset, which
#     is a CPU-tier task: prepare the datasets with requirements/cpu.lock.txt and
#     train with this file.
#
# Note on CUDA: this stack targets CUDA 13 (see the nvidia-*-cu13 wheels), while
# the paper environment targets CUDA 12.8. Check your driver before adopting it.
